# Noxel

Лаунчер Minecraft в чёрно-белом стиле жидкого стекла. У каждого профиля (версия + загрузчик) своя папка с модами, мирами и настройками, поэтому переключаться между версиями можно, ничего не удаляя.

> A black-and-white Minecraft launcher where every version gets its own mods, worlds and settings. Built with Tauri 2 and Rust, no frontend toolchain.

Сайт и документация: **https://mr1s.site** (исходники в папке `сайт/`).

## Возможности

- **Версии и загрузчики.** Все версии Mojang (релизы, снапшоты, старые) и Vanilla, Fabric, Quilt, Forge, NeoForge, OptiFine. Доступность загрузчика проверяется для каждой версии.
- **Свой профиль на каждую версию.** `instances/<профиль>/` с `mods`, `resourcepacks`, `shaderpacks`, `saves`. Профиль можно скопировать целиком.
- **Сборки Noxel.** Noxel Base (Fabric API, Mod Menu, Sodium, Iris), Noxel FPS, Noxel Full ставятся при создании профиля вместе с зависимостями.
- **Два каталога в одном поиске.** Modrinth и CurseForge вперемешку, дубликаты склеиваются. Версии мода (релиз, бета, альфа) собраны с обоих сайтов, любую можно поставить. Описание мода открывается прямо в лаунчере.
- **Удобство.** Пометка «Скачано на 1.21.1 NeoForge», фильтр клиентских модов, обновление модов, свои файлы кнопкой и перетаскиванием, включение и выключение модов, разбор вылетов с кнопкой «Найти мод».
- **Рекомендуемые моды для серверов.** Список хранится на сервере Noxel, его можно менять без выпуска новой версии (в лаунчере для администратора есть редактор).
- **Аккаунты.** Локальные (ник), Noxel (ник и пароль, данные на сервере) и Microsoft. Объёмная анимированная модель скина, история скинов, плащ, время игры, серверы, миры.
- **Скины.** 64×64 со вторым слоем, тонкие руки, старые 64×32. Загрузка на сервер Noxel и готовая команда `/skin url …` для SkinsRestorer.
- **Java не нужна.** Нужная версия скачивается с серверов Mojang.
- **Обновление лаунчера изнутри.** Сборки подписаны Ed25519, подпись и SHA-256 проверяются перед заменой файла.
- **Автовход на серверах.** При запросе `/register` и `/login` лаунчер сам вводит команду с уникальным паролем для сервера, затем ставит скин (`/skin url …`). Вводит через встроенный Java-агент за доли секунды после запроса. Пароль и скин включаются отдельно в настройках (по умолчанию включено).
- **Вкладка «Серверы».** Популярные серверы с онлайном и пингом, поиск, сортировка, список рекомендуемых модов и кнопка «Зайти» (прямой вход).
- **Мониторинг аккаунта.** График времени игры за 14 дней, самая длинная сессия, дни, серверы, живой таймер, активный аккаунт внизу панели.
- **Значок игры.** У окна Minecraft в панели задач логотип Noxel с маленьким значком игры.
- **Установщик с окном.** Галочки (ярлыки, предзагрузка Java и игры), ползунок загрузки, проверка подписи.

## Состав репозитория

| Папка | Что внутри |
|---|---|
| `исходники/` | лаунчер: Rust-бэкенд (`src-tauri/`) и интерфейс (`ui/index.html`, один файл) |
| `установщик/` | установщик на Tauri 2 |
| `сервер/` | API Noxel на Python (только стандартная библиотека), конфиги nginx и systemd, `deploy.sh` |
| `сайт/` | сайт и документация |
| `.github/workflows/` | автоматическая сборка для Linux и Windows |
| `готовый продукт/` | готовые сборки (в git не попадают) |
| `данные/` | данные пользователя: профили, аккаунты, игра (в git не попадают) |

## Сборка и установка

Нужны Rust и WebKitGTK 4.1 (на Linux), для иконок `librsvg`.

```bash
./install.sh --build     # собрать лаунчер, положить в «готовый продукт/Noxel», поставить ярлыки
./install.sh --remove    # убрать ярлыки
```

Установщик собирается отдельно: `cd установщик/src-tauri && cargo build --release --features custom-protocol`.

**Windows (БЕТА).** Код содержит ветки для Windows, а сборку выполняет GitHub Actions (`.github/workflows/release.yml`): запусти workflow вручную или поставь тег `v*`. Версия для Windows **не проверялась на реальной машине**.

## Данные

Если запустить `готовый продукт/Noxel`, данные лежат в соседней папке `данные/`. У установленной копии это `~/.local/share/noxel` (Linux) или `%LOCALAPPDATA%\Noxel` (Windows). Путь можно задать переменной `NOXEL_HOME`.

В `данные/accounts.json` лежат токены входа. Файл не попадает в git, не публикуй его.

## Сервер Noxel

`сервер/noxel-server.py` — аккаунты с паролем (scrypt), скины и плащи с историей, облачная статистика, список серверов, манифест обновлений, прокси CurseForge. Разворачивается на чистом Debian или Ubuntu:

```bash
cd сервер && bash deploy.sh ваш-домен.example
```

Скрипт ставит nginx и certbot, создаёт отдельного пользователя, службу systemd с изоляцией и сертификат. Секреты лежат только на сервере:

- `/etc/noxel/admin.token` — токен администратора (правка списка серверов);
- `/etc/noxel/cf.key` — ключ CurseForge (в лаунчере его нет, запросы идут через прокси сервера).

Адрес сервера задан константой `API` в `исходники/src-tauri/src/skins.rs`. Описание запросов есть на сайте в разделе «API».

## Выпуск релиза

Закрытый ключ подписи хранится в `.keys/release.pem` (папка в `.gitignore`, **никогда не публикуй**). Публичный ключ встроен в `remote.rs` лаунчера и в установщик.

```bash
./publish.sh 0.4.0 "Что нового" "Ещё строка"          # лаунчер и манифест самообновления
WIN_BIN=путь/к/Noxel.exe ./publish.sh 0.4.0 "…"       # то же с Windows-сборкой
./publish-setup.sh linux-x86_64 путь/к/noxel-setup    # установщик для сайта
сайт/deploy-site.sh                                   # обновить сайт
```

Нужен доступ по ssh к серверу (`NOXEL_SSH=root@ваш-домен`, по умолчанию `root@mr1s.site`).

## Проверка

Интеграционные тесты ходят на настоящие серверы и запускают игру:

```bash
cd исходники/src-tauri
T_MC=1.21.1 T_LOADER=fabric T_PRESET=base cargo test --release --features custom-protocol full_launch -- --ignored --nocapture
cargo test --release --features custom-protocol -- merged_catalog noxel_flow updater_verify --include-ignored --nocapture
```

`T_LOADER`: `vanilla`, `fabric`, `quilt`, `forge`, `neoforge`, `optifine`. `T_PRESET`: `base`, `fps`, `full`. Для тестов, пишущих данные, задай `NOXEL_HOME=<пустая папка>`.

## Известные ограничения

- **Windows — БЕТА**: собирается на GitHub Actions, на реальной системе не проверялся.
- **Вход через Microsoft** написан по документации и не проверялся на живом аккаунте. Нужен свой Client ID приложения Azure и одобрение доступа к API Minecraft у Mojang.
- **Старые версии Forge на системах с zlib-ng** (CachyOS, Fedora 40+) не проходят проверку установщика Forge. NeoForge и Fabric не затронуты.
- **Версии 1.8.x** падают под Wayland из-за старой библиотеки LWJGL 2.
- **OptiFine** скачивается с зеркала BMCLAPI; его лицензия запрещает распространение.
- **Плащи** обычный клиент не показывает другим игрокам: серверные плагины передают только подписанные Mojang текстуры.
- Показ загруженного скина в локальном мире пока не реализован. Автовход проверен на Linux с тестовым сервером, настоящие серверы могут писать запросы иначе.
